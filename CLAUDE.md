# Смэш мне в ногу — заметки для Claude Code

Браузерный бадминтон «вид сбоку» для игры с друзьями. Одиночка до 15, против ИИ, онлайн по коду комнаты, тренировка с многоволанкой, общая таблица побед и вход по имени + ПИН.

- Сайт: https://smash-v-nogu.github.io/ (GitHub Pages, ветка `main`, корень репозитория)
- Репозиторий: `smash-v-nogu/smash-v-nogu.github.io`
- Старый адрес `korolevdesgn-gif.github.io/badminton` — только переадресация сюда (репозиторий `korolevdesgn-gif/badminton`, страница переносит профиль через `?from=`). Трогать не нужно.
- База: Supabase, проект `ktpeclypxevbfwtvuwbi`, схема в `supabase/schema.sql`
- Идеи на развитие: `docs/IDEAS.md`

## Как устроено

Всё в одном файле `index.html`: разметка, стили, игра в одном IIFE. Сборки нет, зависимостей нет, кроме PeerJS 1.5.5 с unpkg (грузится асинхронно, только для онлайна) и шрифтов Google (Unbounded, Golos Text и Doto — точечный, только для цифр и кода комнаты в меню). Интерфейс и комментарии в коде — на русском, так и держим.

Разделы скрипта (ищи по `/* =========`):

| Раздел | Что внутри |
|---|---|
| Корт и физика | `COURT=13.4`, `NET=6.7`, `SHORT=1.98`, длина партии `TARGETS = {7: 10, 15: 21}` (до скольки → потолок), выбор в меню `matchLen` (хранится в `bdm-len`), текущая — `game.target`; в сети её задаёт хозяин и шлёт в снимке `g[7]`. Квадратичное сопротивление `K = G / vTerm²`, фиксированный шаг `H = 1/240`, `simulate()`. Решатели ударов `solveSpeed / solveFixed / solveFlat / solveAngle` |
| Состояние игры | `game`, игроки `P[0]` (слева) и `P[1]`, волан `sh`; `setupMode(mode)`, `newGame`, `setupServe` |
| Удары | `hitQuality` (чистый удар `p.perfect`), `canHit`, `doHit(p, key)` — клир/дроп/смэш и их «низовые» варианты, добивание `kill` (смэш по волану у сетки выше троса, зона `killZone`), прицел `place` (±1) от направления в момент удара; срыв ИИ `fail` (по `err`); `doServe`, `launch` |
| Розыгрыш | `onLand` (ястребиный глаз через `fx('mark')`), `award` |
| ИИ | `makePlan` (точку удара ищет `planFrom`), `aiChooseShot`, `aiUpdate`; уровни в `DIFFS` (`react, speed, timing, spread, judgeOut, aggr, power, err, perfect, risk`, тактика `tact` у среднего, сложного и умного, у умного ещё `read`). Выбор удара — `aiPickKey`. После своей сетки ИИ ждёт ближе к ней (`NET_FOLLOW`), точки в зоне добивания `planFrom` предпочитает. Для тестов `ai.bot` — однообразный (`{ key, place }`) или случайный (`'any'`) соперник |
| Чтение (умный ИИ) | `smart` — физика как у сложного, плюс модель ударов соперника: ситуация = какой удар ИИ отправил, куда тот падает, давление (`readAim`); что ответил соперник (`readObserve`), сглаженно и с забыванием, с подстраховкой ситуацией попроще. Уверенный прогноз (`READ.THR`, запас `READ.Z`) сдвигает точку ожидания не дальше `READ.SHIFT` = 0,9 м (`readHome`, `readLean`); угадал — всплывашка «Читаю тебя» (раз за розыгрыш). Память между партиями — `READ.CARRY` от прошлой, в `bdm-read` (по pid) |
| Шаг симуляции | `updatePlayer` (выносливость `p.sta`, давление `p.press`, замах `p.swing`), `updateShuttle`, `step`, `endGame`, `showOver` |
| Ввод | `BIND` по режимам, `humanAxis`, `humanAction`, сенсорные кнопки |
| Отрисовка | косая проекция глубины `X(x, z)` / `Y(y, z)` (`DZX`, `DZY`), флаг `mirror` у гостя; табло на стене `drawWall`, игроки, волан, всплывашки |
| Тренировка | режим `'train'`: робот `P[1]` подаёт 20 воланов (`FEEDS`), цели `ZONES`, очки и серии, `trainStart / trainSetup / trainFeed / trainTick / trainLand / trainEnd` |
| Интерфейс | меню, табло `updateBoard`, подсказки `updateHint`, настройки (шестерёнка). Вёрстка меню — стиль «Табло зала» (CSS-раздел «Главный экран»), логотип «Прямо в кеду» — `<symbol id="logoKeda">`, он же в favicon и `og.png` |
| Сеть | `Net`: хост авторитетен. Гость шлёт `t:'in'` (позиция, номер и тип удара, реакции), хост шлёт снимки `t:'st'` и журнал событий `fx()` → `applyFx()`. Транспорты: PeerJS (`PEER_PREFIX 'bdm-proto-26-'`, коды из `CODE_ABC`) и BroadcastChannel для локальной проверки `?net=local`. Ретранслятор TURN Cloudflare: ключи `iceServers()` берёт у функции Supabase `turn`, не ответила за 3 с — только STUN. Гость, не вошедший за 15 с, видит шаг, где застрял (`stage()`: server / answer / ice → `netErrText`). Сводка сети за матч `NetStats` (путь из `getStats`: напрямую / ретранслятор, UDP / TCP; пинг игры и соединения, замирания дольше `NET_GAP` = 250 мс, темп сообщений и кадров) — `take()` в `applyFx('match')`, лежит в `store.net` до отправки |
| Профиль и таблица | `profile` (pid, имя, стиль, `acc`, `pin`), `store` (записи матчей, имена, рекорды, `alias`, `train`), `standings()`, склейка профилей `canon(pid)`, окно входа `openNameDlg / setDlgMode` (режимы new / login / pin / edit) |
| Общая таблица | `cloudReq`, `cloudSync` (пушит матчи и игрока, тянет matches, players, aliases), вход через RPC `bdm_login`. Онлайн-матч уходит в `bdm_sync` с полем `net` — своей сводкой сети; матч, который уже записал друг, отправляется снова ради сводки |
| Лобби | таблица `rooms`: хост объявляет комнату, пульс раз в 20 с, список «Ждут соперника» |
| Реакции | 5 фраз на клавишах 1–5 (новые — в конец `REACTS`: номер уходит по сети, GG = 3), облачко над игроком; против ИИ он отвечает сам (`aiReact`) и смеётся над глупой ошибкой игрока (`sillyMiss`: в сетку, недолёт подачи, аут дальше 0,5 м, прозевал волан в метре от себя; не чаще раза в 3 розыгрыша, шанс 0,6) |
| Правила | 11 шагов с анимацией ударов (`RULE_STEPS`, `rShow`), открываются при первом входе. Проигрыватель общий: `openDeck(шаги, i, ярлык, назад)` показывает и правила, и пункты «Что нового». Демо собирает `buildDemo` (`dm.view` — приближение кадра, у удара `from` — подлёт с половины соперника, `play` — скорость показа) |
| Что нового | `NEWS` — список обновлений от нового к старому, фишка «Что нового» в шапке меню (`#newsBtn`) и окно `#news`. Вернувшийся игрок, который не видел свежее обновление (`bdm-news` < `NEWS[0].id`), получает окно при входе в меню (`newsInit / maybeNews`); новичку вместо него — правила, пришедшему по ссылке в комнату окно не показываем |
| Цикл | `frame`, `start` |

Для отладки в консоли есть `window.__bdm` (game, P, sh, cfg, simulate, Net, store, profile, standings, cloudSync, openRules, READ, readReset и т. д.).

## Запуск и проверка

```bash
python3 -m http.server 8765
# игра:             http://localhost:8765/
# два профиля:      http://localhost:8765/?p=1  и  ?p=2   (p — одна цифра, отдельный localStorage)
# онлайн без сети:  http://localhost:8765/?net=local&p=1  и  ?net=local&p=2 в двух вкладках
```

Тесты — сценарии на Playwright в `tests/` (см. `tests/README.md`). В реальную базу они не пишут: Supabase подменён, отключён или открыт только на чтение. После деплоя — `tests/test_live.py` по живому сайту.

Внутри артефакта claude.ai онлайн выключен (`inClaude()`), там же нет облака.

## Деплой

Пуш в `main` → GitHub Pages обновляется за минуту. Проверять после деплоя с параметром в адресе, чтобы обойти кэш: `https://smash-v-nogu.github.io/?v=<коммит>`.

## База (Supabase)

Ключ в коде публичный (`sb_publishable_…`), поэтому таблицы с ним только читаются. Пишет игра только через функции, которые проверяют ПИН (тот же счётчик ошибок и блок, что у входа; общая проверка — `bdm_auth`, снаружи не вызывается):
- `bdm_sync(p_pid, p_pin, p_matches, p_best)` — свои матчи (свой id или склеенный с аккаунтом; чужие пропускает) и свои рекорды (только растут, имя берётся из аккаунта). Поле `net` онлайн-матча — в `net_stats`, одна сводка на игрока и матч
- `bdm_room(p_pid, p_pin, p_code, p_status)` — своя комната в лобби: `open` / `playing` / `gone`, одна на игрока
- Без ПИНа (`profile.acc` + `profile.pin`) игра в базу не пишет, только читает. Если база ответила `pin` или `noacc`, игра сбрасывает вход и спросит ПИН заново.

Таблицы:
- `matches` — матчи (`k='ai'` или `'net'`)
- `players` — имя и рекорды по pid (`best_smash`, `best_rally`, `best_train`)
- `rooms` — открытые комнаты для лобби, старше часа удаляются
- `net_stats` — сводка сети каждой стороны онлайн-матча (`match_id`, `pid`, `d` jsonb до 1500 байт; ключи описаны в `schema.sql`). Разбирать жалобы «лагало»: `curl '…/rest/v1/net_stats?match_id=eq.<id>' -H 'apikey: <ключ>'`, id матча — из `matches`. С 18.11.2026, миграция `20261118_net_stats.sql`
- `accounts` — имя + хэш ПИНа, напрямую недоступна, только через `bdm_login(p_name, p_pin, p_pid, p_mode)`; режимы `new`, `login`, `rename`; 8 неверных ПИНов → блок на 15 минут
- `aliases` — склейка старых id с аккаунтом, клиенты пересчитывают таблицу через `canon()`
- `legacy_players` — снимок игроков до появления входа по ПИНу

Функция `turn` (Edge Function, код в `supabase/functions/turn/index.ts`) выдаёт временные ключи ретранслятора TURN Cloudflare на 6 часов. Секреты `CF_TURN_KEY_ID` и `CF_TURN_API_TOKEN` лежат только в Supabase (Edge Functions → Secrets), проверка JWT у функции выключена (публичный ключ — не JWT). Ключи отдаются только страницам с `smash-v-nogu.github.io` и `localhost`. Меняешь код функции — вставь его заново в дашборде (Edge Functions → turn → Code) и закоммить сюда же. Лимит Cloudflare: 1000 ГБ в месяц бесплатно, дальше $0,05 за ГБ; партия через ретранслятор — порядка 10 МБ.

Любые изменения схемы — через SQL Editor в дашборде Supabase, и сразу дописывать их в `supabase/schema.sql` (итоговое состояние) и в `supabase/migrations/` (что именно применяли). Перед применением — `cd tests/db && npm install && npm test`: схема и миграция гоняются в PGlite под ролью `anon`.
Публичная схема известна всем (репозиторий открыт), поэтому всё, что не должно делать любой посетитель, закрывается правами в базе, а не в коде игры.

## Решения и подводные камни

- Свой игрок всегда слева: у гостя корт зеркалится (`setMirror`), «вперёд» — вправо по экрану.
- `?p=` — только одна цифра (`SLOT`), иначе берётся основной профиль.
- Имена уникальны через аккаунты; одинаковые имена у старых профилей в таблице получают номер («Саша 2»).
- Профили без ПИНа один раз видят окно «Защити профиль».
- Управление мышью (зажми, потяни, отпусти) было сделано и убрано 17.11.2026. Код в истории: коммит `9e151c6`. Звук натяжения возвращать не нужно.
- Умный ИИ (`smart`) не сильнее и не быстрее сложного — все физические параметры те же, выигрыш только от предвидения. Против разнообразного соперника он как сложный, против однообразного заметно сильнее, а хитрец, который меняет привычку каждые пару розыгрышей, обыгрывает его даже лучше, чем сложного. Замеры и проверка — `tests/test_ai_smart.py`, таблица в `tests/README.md`.
- Уровень `smart` в `matches.lv` открывает миграция `supabase/migrations/20261118_smart_level.sql` (сначала она, потом деплой клиента). Если базу не обновили, `bdm_sync` пропускает матч с умным, а `cloudPush` оставляет его в очереди и шлёт снова — матч не теряется.
- Баланс ИИ: средний против среднего — около 12 ударов за розыгрыш, стороны симметричны; сложный выигрывает у среднего около 90% партий, типичный счёт 15:9 (около 62% очков). Таблица замеров — в `tests/README.md`. После правок физики или ИИ гоняй `tests/test_ai_balance.py` (ловит бесконечные розыгрыши, сдвиг баланса и однообразного бота, который обыгрывает сложного) и `tests/test_ai_smart.py`.
- Онлайн без ретранслятора не работает у части пар: мобильный интернет, VPN и рабочий Wi‑Fi не пускают прямое соединение. Публичные TURN PeerJS (`eu-0/us-0.turn.peerjs.com`), на которые игра полагалась, исчезли (на 18.11.2026 у них нет даже DNS), гость висел 15 с на «Подключаемся…». С 18.11 ретранслятор свой (функция `turn`). Проверка — `tests/test_turn.py`.
- Новое обновление в «Что нового» — объект в начало `NEWS`, `id` = дата выкатки `ГГГГ-ММ-ДД`, второе обновление за день — с буквой (`2026-11-18b`): по `id` игрок видит «новое», а окно пишет «Сегодня вышло обновление». У каждого пункта короткая строка `s` и текст `d`; удары и механики — с `demo` из `buildDemo`. Пункты описывают только то, что реально уходит в этот деплой. Только то, что игрок заметит в игре (удары, механики, ИИ, режимы, управление, реакции); технические детали — связь, ретранслятор, починки — не пишем (решение Кирилла 18.11).
- Таблица в меню показывает всех игроков: лишние строки прокручиваются внутри плиты (`.lb-scroll`), шапка и своя строка прилипают к краям. На десктопе (от 1080 px) таблица занимает всю высоту меню справа, «Управление» стоит под двумя левыми колонками; высоту плите задают соседние плиты (`contain: size`), сама она их не растягивает.
- Тактика ИИ (`tact`, 18.11.2026): под давлением свеча и клир проигрывают (высокий волан давления не снимает), поэтому средний, сложный и умный под давлением реже поднимают волан, у сетки бьют тугую сетку, от смэша защищаются блоком и драйвом. Без неё однообразный бот (всегда дроп или всегда смэш) обыгрывал сложного. Цифры — в `tests/README.md`, раздел «Однообразный соперник».
- Срыв тугого прицела у живого игрока (`slip`, `TIGHT_RISK`) пробовали 18.11.2026 в ветке `wip/tact-slip` и не выкатили (решение Кирилла): он наказывал случайно за правильно нажатый удар. Дыру «дроп и сетку нечем наказать» закрывают тактика ИИ и добивание у сетки.
- Добивание у сетки (18.11.2026): смэш по волану ниже 1,9 м, который у сетки идёт выше линии `NET_H + KILL_UP + KILL_SLOPE·d` (8 см над тросом + 25 см на метр от сетки), бьёт коротко и круто вниз (`v = 'kill'`, на табло и в рекорд смэша не идёт). Зачем: раньше всё ниже 1,9 м было нечем атаковать, и дроп/сетка не наказывались — однообразный дропер обыгрывал сложный ИИ. Над линией оказываются сетка с плохого контакта (`weak`) и из-под пола (`NET_LOW_UP`), обычный дроп; чистая сетка сверху и острый дроп — ниже. Угол сетки уточняется до 0,5° (`solveFlat(..., fine)`): с шагом 2,5° «тугая» сетка шла на 15–50 см над тросом. Поэтому тугая сетка с нечистого контакта чаще цепляет трос. Проверка — `tests/test_kill.py`.
- Удар, взятый над самым тросом (`canHit` пускает на 4 см за сетку), сетку не пересекает — решатели считают его прошедшим (`overNet`). Раньше `solveAngle` в этом случае задирал угол, и удар улетал в аут.
- Компенсация лага (`pastReach`, окно удара гостя `0.17 + Net.lagGame()`) берёт пинг, который хозяин меряет сам: в снимке метка `hs`, гость возвращает её в своём вводе (`he`), хозяин считает время до эха (18.11.2026). Раньше пинг присылал сам гость (`m.rtt`), и его можно было поменять из консоли, расширив себе окно удара. Потолок — 0,3 с.
- Хозяин открыл комнату и ушёл играть с ИИ или на тренировку — комната закрывается и уходит из лобби (`startGame` → `netClose`). Раньше вошедший друг выдёргивал хозяина из партии в онлайн.
- `game.stats` копится с загрузки страницы (включая демо в меню), между партиями не обнуляется.
- Коммиты подписываются как `korolevdesgn-gif <korolevdesgn-gif@users.noreply.github.com>`.
