# Смэш мне в ногу — заметки для Claude Code

Браузерный бадминтон «вид сбоку» для игры с друзьями. Одиночка до 15, против ИИ, онлайн по коду комнаты, тренировка с многоволанкой, общая таблица побед и вход по имени + ПИН.

- Сайт: https://smash-v-nogu.github.io/ (GitHub Pages, ветка `main`, корень репозитория)
- Репозиторий: `smash-v-nogu/smash-v-nogu.github.io`
- Старый адрес `korolevdesgn-gif.github.io/badminton` — только переадресация сюда (репозиторий `korolevdesgn-gif/badminton`, страница переносит профиль через `?from=`). Трогать не нужно.
- База: Supabase, проект `ktpeclypxevbfwtvuwbi`, схема в `supabase/schema.sql`
- Идеи на развитие: `docs/IDEAS.md`

## Как устроено

Всё в одном файле `index.html`: разметка, стили, игра в одном IIFE. Сборки нет, зависимостей нет, кроме PeerJS 1.5.5 с unpkg (грузится асинхронно, только для онлайна) и шрифтов Google (Unbounded, Golos Text). Интерфейс и комментарии в коде — на русском, так и держим.

Разделы скрипта (ищи по `/* =========`):

| Раздел | Что внутри |
|---|---|
| Корт и физика | `COURT=13.4`, `NET=6.7`, `SHORT=1.98`, `TARGET=15`, `CAP=21`. Квадратичное сопротивление `K = G / vTerm²`, фиксированный шаг `H = 1/240`, `simulate()`. Решатели ударов `solveSpeed / solveFixed / solveFlat / solveAngle` |
| Состояние игры | `game`, игроки `P[0]` (слева) и `P[1]`, волан `sh`; `setupMode(mode)`, `newGame`, `setupServe` |
| Удары | `hitQuality` (чистый удар `p.perfect`), `canHit`, `doHit(p, key)` — клир/дроп/смэш и их «низовые» варианты, прицел `place` (±1) от направления в момент удара, `doServe`, `launch` |
| Розыгрыш | `onLand` (ястребиный глаз через `fx('mark')`), `award` |
| ИИ | `makePlan`, `aiChooseShot`, `aiUpdate`; уровни в `DIFFS` (`react, speed, timing, spread, judgeOut, aggr, power, err, perfect, risk`) |
| Шаг симуляции | `updatePlayer` (выносливость `p.sta`, давление `p.press`, замах `p.swing`), `updateShuttle`, `step`, `endGame`, `showOver` |
| Ввод | `BIND` по режимам, `humanAxis`, `humanAction`, сенсорные кнопки |
| Отрисовка | косая проекция глубины `X(x, z)` / `Y(y, z)` (`DZX`, `DZY`), флаг `mirror` у гостя; табло на стене `drawWall`, игроки, волан, всплывашки |
| Тренировка | режим `'train'`: робот `P[1]` подаёт 20 воланов (`FEEDS`), цели `ZONES`, очки и серии, `trainStart / trainSetup / trainFeed / trainTick / trainLand / trainEnd` |
| Интерфейс | меню, табло `updateBoard`, подсказки `updateHint`, настройки (шестерёнка) |
| Сеть | `Net`: хост авторитетен. Гость шлёт `t:'in'` (позиция, номер и тип удара, реакции), хост шлёт снимки `t:'st'` и журнал событий `fx()` → `applyFx()`. Транспорты: PeerJS (`PEER_PREFIX 'bdm-proto-26-'`, коды из `CODE_ABC`) и BroadcastChannel для локальной проверки `?net=local` |
| Профиль и таблица | `profile` (pid, имя, стиль, `acc`, `pin`), `store` (записи матчей, имена, рекорды, `alias`, `train`), `standings()`, склейка профилей `canon(pid)`, окно входа `openNameDlg / setDlgMode` (режимы new / login / pin / edit) |
| Общая таблица | `cloudReq`, `cloudSync` (пушит матчи и игрока, тянет matches, players, aliases), вход через RPC `bdm_login` |
| Лобби | таблица `rooms`: хост объявляет комнату, пульс раз в 20 с, список «Ждут соперника» |
| Реакции | 4 фразы на клавишах 1–4, облачко над игроком; против ИИ он отвечает сам (`aiReact`) |
| Правила | 11 шагов с анимацией ударов (`RULE_STEPS`, `rShow`), открываются при первом входе |
| Цикл | `frame`, `start` |

Для отладки в консоли есть `window.__bdm` (game, P, sh, cfg, simulate, Net, store, profile, standings, cloudSync, openRules и т. д.).

## Запуск и проверка

```bash
python3 -m http.server 8765
# игра:             http://localhost:8765/
# два профиля:      http://localhost:8765/?p=1  и  ?p=2   (p — одна цифра, отдельный localStorage)
# онлайн без сети:  http://localhost:8765/?net=local&p=1  и  ?net=local&p=2 в двух вкладках
```

Тесты — сценарии на Playwright в `tests/` (см. `tests/README.md`). В реальную базу они не пишут: Supabase подменён, отключён или открыт только на чтение. После деплоя — `tests/test_live.py` по живому сайту.

Внутри артефакта claude.ai онлайн выключен (`inClaude()`), там же нет облака.

## Деплой

Пуш в `main` → GitHub Pages обновляется за минуту. Проверять после деплоя с параметром в адресе, чтобы обойти кэш: `https://smash-v-nogu.github.io/?v=<коммит>`.

## База (Supabase)

Ключ в коде публичный (`sb_publishable_…`), всё закрыто RLS:
- `matches` — матчи (`k='ai'` или `'net'`), читать и добавлять можно, менять и удалять нельзя
- `players` — имя и рекорды по pid (`best_smash`, `best_rally`, `best_train`), upsert
- `rooms` — открытые комнаты для лобби
- `accounts` — имя + хэш ПИНа, напрямую недоступна, только через `bdm_login(p_name, p_pin, p_pid, p_mode)`; режимы `new`, `login`, `rename`; 8 неверных ПИНов → блок на 15 минут
- `aliases` — склейка старых id с аккаунтом, клиенты пересчитывают таблицу через `canon()`
- `legacy_players` — снимок игроков до появления входа по ПИНу

Любые изменения схемы — через SQL Editor в дашборде Supabase, и сразу дописывать их в `supabase/schema.sql`.

## Решения и подводные камни

- Свой игрок всегда слева: у гостя корт зеркалится (`setMirror`), «вперёд» — вправо по экрану.
- `?p=` — только одна цифра (`SLOT`), иначе берётся основной профиль.
- Имена уникальны через аккаунты; одинаковые имена у старых профилей в таблице получают номер («Саша 2»).
- Профили без ПИНа один раз видят окно «Защити профиль».
- Управление мышью (зажми, потяни, отпусти) было сделано и убрано 17.11.2026. Код в истории: коммит `9e151c6`. Звук натяжения возвращать не нужно.
- Баланс ИИ: средний против среднего — около 12 ударов за розыгрыш, стороны симметричны; сложный выигрывает у среднего около 90% партий, типичный счёт 15:9 (около 62% очков). Таблица замеров — в `tests/README.md`. После правок физики или ИИ гоняй `tests/test_ai_balance.py`: он ловит бесконечные розыгрыши и сдвиг баланса.
- Коммиты подписываются как `korolevdesgn-gif <korolevdesgn-gif@users.noreply.github.com>`.
