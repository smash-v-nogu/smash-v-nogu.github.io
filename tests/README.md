# Сценарии на Playwright

Каждый файл — самостоятельный сценарий: открывает игру в браузере, играет и проверяет результат. В настоящую базу ничего не пишется: Supabase подменён, отключён или (в `test_live.py`) открыт только на чтение.

```bash
pip install playwright && python -m playwright install chromium
python3 -m http.server 8765      # из корня репозитория, в отдельном терминале
cd tests
python3 test_login.py            # вход по имени и ПИН
python3 test_online.py           # онлайн через BroadcastChannel
python3 test_peer_rejoin.py      # настоящий PeerJS: призрак и вторая вкладка не занимают комнату (нужен интернет)
python3 test_turn.py             # ретранслятор: ключи от функции turn, без неё — напрямую, сбой сети назван честно (нужен интернет, около минуты)
python3 test_training.py         # тренировка с многоволанкой (идёт пару минут)
python3 test_length.py           # длина партии «до 7 / до 15», в сети её задаёт хозяин
python3 test_ai_balance.py       # баланс ИИ на ускоренной симуляции (около минуты)
python3 test_ai_smart.py         # умный ИИ: читает однообразного, с разнообразным — как сложный (около трёх минут)
python3 test_news.py             # «Что нового»: окно при входе только вернувшемуся, пункт с анимацией и назад к списку; таблица на 21 игрока
```

База — схема и миграции в PGlite (настоящий Postgres в WebAssembly) под ролью `anon`, как у игры с публичным ключом: прямая запись закрыта, `bdm_sync` / `bdm_room` пишут только своё, перебор ПИНа блокируется. Второй прогон накатывает миграцию на старую схему по шагам:

```bash
cd tests/db && npm install && npm test
```

После деплоя — проверка живого сайта, локальный сервер не нужен:

```bash
cd tests && python3 test_live.py
```

Она читает настоящую Supabase (любая запись обрывается и роняет тест), соединяет два браузера через настоящий PeerJS, доигрывает матч против ИИ и проверяет, что настоящая база не даёт писать напрямую. Пробы ничего не записывают даже в открытую базу: строки заведомо кривые, фильтры ни с чем не совпадают.

Переменные окружения:
- `BASE_URL` — другой адрес локальной игры (если 8765 занят: `BASE_URL=http://127.0.0.1:8766/index.html`)
- `CHROME` — путь к своему Chrome вместо Chromium от Playwright (на Маке: `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`)
- `LIVE_URL` — другой адрес для `test_live.py`, `SHOTS` — папка для его скриншотов
- `SECS` — игровых секунд на случай в `test_ai_balance.py` и `test_ai_smart.py`, `HTML` — подставить другую версию `index.html` (сравнить со старым коммитом: `git show <коммит>:index.html > /tmp/old.html && HTML=/tmp/old.html python3 test_ai_balance.py`)

## Баланс ИИ (замер 17.11.2026, по 30000 игровых секунд на случай)

| Слева против справа (стиль «Техника») | Очки слева | Партии слева | Средний счёт | Ударов за розыгрыш |
|---|---|---|---|---|
| средний — средний | 51% | 49 из 83 | 13,4 : 12,7 | 11,9 (макс 41) |
| сложный — средний | 62% | 81 из 89 | 14,9 : 9,0 | 12,7 (макс 55) |
| средний — сложный | 37% | 10 из 91 | 8,8 : 14,8 | 12,6 (макс 48) |
| лёгкий — средний | 22% | 0 из 138 | 4,3 : 15,0 | 8,6 (макс 31) |

Стиль сдвигает долю очков сложного против среднего в пределах 61–71%, но не переворачивает исход. Те же цифры на первом коммите `2736724` — баланс с тех пор не менялся.

## Умный ИИ (замер 18.11.2026, по 24000 игровых секунд на случай)

Физика у умного та же, что у сложного, разница только в чтении: он копит, каким ударом и куда соперник отвечает в похожей ситуации, и при уверенном прогнозе ждёт до 0,9 м ближе к нужной точке. Соперники — боты на физике сложного (`ai.bot` в `_util.ai_case`): однообразный всегда жмёт одну кнопку с одним прицелом, случайный — любую кнопку и любой прицел.

| Соперник (стиль «Техника») | Очки у сложного | Очки у умного | Разница | «Читаю тебя» |
|---|---|---|---|---|
| средний ИИ | 64,6% | 62,5% | −2,1 | в 10% розыгрышей |
| случайный бот | 61,6% | 61,5% | 0 | в 2–3% |
| однообразный: острый дроп / тугая сетка | 39,7% | 57,2% | +17,5 | в 96% |
| однообразный: глубокий клир | 74,7% | 79,4% | +4,7 | почти всегда |
| однообразный: смэш (снизу — драйв) | 44,2% | 45,0% | +0,8 | в 43% |
| хитрец: меняет привычку каждые 45 с | 61,4% | 57,3% | −4,1 | |
| хитрец: меняет привычку каждые 20 с | 56,9% | 61,0% | +4,1 | |

- С разнообразным соперником умный играет как сложный: уверен он лишь в 4–10% ударов, из них угадывает около половины.
- Однообразного дропера сложный не держит (проигрывает 3 партии из 4), умный выигрывает у него 4 из 5.
- Против смэша чтение не помогает: смэш долетает за 0,4 с, и решает качество приёма, а не то, где ИИ стоял.
- Хитрец, который держит одну привычку пару розыгрышей и меняет её, наказывает умного сильнее, чем сложного: тот уверенно встаёт не туда. Так и задумано — игрок может обмануть, меняя удары.

`test_ai_smart.py` проверяет то же: сравнения «как сложный» на 30000 с (шум разницы около 1,6 п.п.), однообразного — на 15000 с: против среднего и случайного умный не сильнее сложного больше чем на 5 п.п. и не слабее больше чем на 8, против однообразного дропера он сильнее на 8 п.п. и больше. Плюс игра через меню: «Читаю тебя» появляется, память лежит в `bdm-read` и переходит в следующую партию, матч записан с уровнем `smart` и уходит в общую таблицу, а если база ещё без миграции `20261118_smart_level.sql` и пропустила его — остаётся в очереди и уходит со следующей синхронизацией. Сама миграция проверяется в `tests/db` (оба режима: схема целиком и старая схема → миграции по шагам).
